**Branch**: `001-build-infrastructure` | **Date**: 2026-09-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-build-infrastructure/spec.md`

## Summary

Restore the project's Gradle wrapper at the version already pinned (8.9), and document the
Firebase configuration requirement in the README. Together these clear blockers B1 and B2 from
`.specify/memory/baseline-analysis.md`, which currently make the constitution's Definition of
Done (Principle XI) unreachable for every feature, because no automated check can run.

The wrapper is generated by the official Gradle 8.9 distribution already validated in the local
wrapper cache, run on Android Studio's bundled JDK 21. No application source is touched, no
dependency is added, and no version is upgraded.

**Deviation from the original plan — `.gitattributes` added**: this file was not in the original
file plan. It was added after staging `gradlew` produced a Git warning that LF would be converted
to CRLF, traced to `core.autocrlf=true` in the Git for Windows system config. Left unfixed, the
committed `gradlew` would be unrunnable on Linux and macOS, contradicting FR-001 for non-Windows
clones and the spec's stated line-endings edge case. The rules are scoped to the wrapper files
only, not a repository-wide normalisation policy. Full reasoning and verification evidence in
[research.md](./research.md) R-4.

**Structure Decision**: no structural change. The project remains a single Gradle module `app`
with a flat `com.sipsense.app` package. This feature only restores repository-root build entry
points and documentation, so the existing layout recorded in the constitution's Current
Architectural Baseline is preserved exactly.
